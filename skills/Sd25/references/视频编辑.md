# 视频编辑

用户要求修改已有视频的画面，或沿用原视频内容重新适配画幅、总时长时，读取本文件。继续遵守 [主文件](../SKILL.md) 的意图保真、素材职责、引用保真与输出合同。

## 画幅与时长兼容性闸门

在解析用户原始 Prompt 时、构造任何 API 请求之前主动执行本闸门。不得等待 API 报错，也不得依赖 TaskTypeConstraint 再补写声明。先读取参考视频的真实画幅和时长，并与用户明确要求的目标输出规格比较：

- 目标画幅与参考视频不同：不得判为视频编辑，按普通视频生成处理。
- 目标时长与参考视频相差超过约 0.3 秒：不得判为视频编辑。用户明确要求向前或向后续写时按视频延长处理，其他时长变化按普通视频生成处理。
- 参考视频已经提供但规格无法读取，或用户要求参考原视频但没有提供参考视频时，先根据原始 Prompt 的明确意图判断。如果用户明确表达“横屏转竖屏”“竖屏转横屏”“缩短为 8 秒”“改为 20 秒”或没有延长方向的“扩展为 20 秒”等相对变化，保守判定存在画幅或目标总时长冲突，避免视频编辑并按普通视频生成处理；只有目标比例或时长、没有表达相对变化时，不声称已经确认冲突。明确写出“向前延长”“向后延长”或“续写”等明确延长意图仍按视频延长处理。
- 只有目标画幅和基本时长与参考视频一致或均未指定，并且用户要求修改原视频中的明确对象、区域或声音时，才判为视频编辑。

“转换、调整、修改、改成、重构”等动词本身不构成视频编辑。不得仅因原始 Prompt 使用“转换、调整、修改、保持不变”等词而触发该声明。规格不兼容而进入普通视频生成时，参考视频只作为内容、人物、场景、动作、时序、镜头和声音参考；画幅和总时长仅作为页面或接口参数，最终 Prompt 不使用“编辑、修改、转换原视频”等表达，也不承诺逐帧或像素级完全一致。

只有确认或保守判定存在上述画幅或时长冲突时，才在优化后的最终 Prompt 中主动加入完整句：`请注意这不是视频编辑。` 在结构化 Prompt 中，该句直接紧跟 `【生成目标】` 的目标句，不另起段落。该句是路由消歧声明，不是对画面内容的负向约束。不得对真实视频编辑、视频延长、首帧或首尾帧生成、没有规格冲突的普通生成任务添加。用户已经写出相同或等价声明时只保留一次，不得重复。

例如，`将视频1转换为9:16竖屏画面，保持原有内容完全不变，仅调整画幅构图` 应判定为普通视频生成；视频1只承担纯参考职责，9:16 作为生成参数。

插入位置示例：

```text
【生成目标】
以@视频1为完整内容参考生成视频，保持原有内容不变，仅重新适配构图。请注意这不是视频编辑。

【参考素材职责】
@视频1用于可见主体、场景、动作、事件时序、镜头和声音参考。

【事件脚本】
完整沿用@视频1中的事件顺序、动作轨迹、镜头变化以及开始和结束状态，不新增、删除或改写原有事件。

【保持一致】
保持@视频1中的可见主体及数量、场景、道具、空间关系、动作顺序、镜头与声音关系和结局状态一致，仅调整构图组织。
```

目标画幅通过页面或接口参数设置，不写入最终 Prompt。

闸门判为普通生成时，回到主文件的视频生成流程；判为视频延长时，读取 [视频延长](视频延长.md)。仅判为视频编辑时使用下方编辑模板。只修改声音时，使用 [声音编辑](声音编辑.md) 的模板。

## 路由自检

- 规格不兼容的参考生成已包含一次 `请注意这不是视频编辑。`；真实视频编辑、视频延长、首帧或首尾帧生成及没有规格冲突的普通生成没有自动添加该声明。
- 参考视频规格不可读取时，已根据原始 Prompt 的明确画幅或时长意图执行兼容性判断，保留原有视频引用，且没有声称已读取或核对参考视频规格。

## 参数规则

- **视频编辑**：视频编辑会自动锁定输入视频的画幅比例和基本时长，两者不支持另行设置；输出时长受输入帧处理影响，可能与原视频存在最大约 0.3 秒的差异。

用户要求另设自动锁定的画幅或时长时，不询问，也不把冲突要求写入 Prompt 或用于规划；先输出最佳 Prompt，再最多追加一条 `参数提示：`，只说明冲突规则和提交前动作。没有冲突时不输出参数提示。

例如：`参数提示：视频编辑会自动保持输入视频的画幅比例和基本时长，不能另行设置为 16:9 和 20 秒；以上 Prompt 已按原视频时间线编写。`

## 输入建议

视频编辑通常优先使用 20 秒以内的原视频和 1 至 5 张参考图；这是推荐范围，不是硬上限，硬输入范围仍按主文件的素材规格预检执行。

## 视频编辑模板

编辑任务必须把一条原视频定义为唯一编辑母版，不能只描述目标画面而退化成重新生成。

画面编辑先逐一盘点原视频中所有可见主体类别，包括用户点名和未点名的人物、真人、模型、动物、道具、前景物体与背景主体；为每一类明确写出替换、删除或保持原样。不得漏掉未被用户点名的真人、模型、道具或背景主体。用户没有要求处理的对象默认保持原样；只有用户明确要求整组替换或目标画面只保留指定对象时，才把对应整组纳入删除或替换范围。

如果当前 Agent 无法完整查看原视频或只有稀疏预览，不得声称已经穷举所有对象。在明确写完用户指定的替换、删除和保持对象后，增加兜底句：`除以上明确修改对象外，@视频1中其他可见人物、道具和背景元素保持原样，不参与替换或删除。` 如果用户明确要求目标画面只保留指定对象，则把这条兜底改为按用户要求删除其余对象。

每条视频编辑 Prompt 都必须包含以下两种范围闭环之一，不能省略范围闭环：

- 局部修改：`除以上明确修改对象外，@视频1中其他可见人物、道具和背景元素保持原样，不参与替换或删除。`
- 用户明确要求只保留目标对象：`除以上明确保留对象外，删除@视频1中的其他可见主体；不新增未指定对象。`

原视频主体盘点只决定哪些对象替换、删除或保持，不能借此改变用户已经指定的目标素材集合。用户已经明确某个编辑对象采用@图片3时，即使其他图片更清晰或内容相似，也不得把未点名图片追加为该对象的外观、服装、群体或辅助参考；这些素材继续列入 `【未采用素材】`。

```text
【编辑目标】
编辑@视频1，只把<原对象或区域>修改为<目标内容>。

【原视频职责】
@视频1是唯一编辑母版，负责原始场景、机位、镜头运动、动作轨迹、遮挡关系和事件顺序。

【目标素材职责】
@图片1用于<目标主体、背景或商品>的<外观、结构或材质>，不采用<无关背景、人物或构图>。

【编辑对象与范围】
只修改<明确对象和区域>。全片目标对象数量为<数量>。不修改<需要保持的内容>。
除以上明确修改对象外，@视频1中其他可见人物、道具和背景元素保持原样，不参与替换或删除。

【时间线继承】
<目标对象>继承<原对象>每次出现、运动、遮挡和离开的时点、持续时长、路径与速度变化。
其他人物动作、镜头运动、镜头切换和事件顺序保持@视频1。
```

主体替换时说明原对象和目标对象；背景替换时明确只修改主体轮廓之外的背景；局部编辑时明确区域、属性和保持内容；增加或删除对象时说明数量、位置、出现时机和受影响范围。

动态主体替换填写示例：

```text
【编辑目标】
编辑@视频1，只把经过长椅前方的红色自行车和骑行者替换为@图片1中的深灰色电动巡逻车。

【原视频职责】
@视频1是唯一编辑母版，负责公园道路、长椅上的两个人、机位、镜头运动、原骑行者的运动槽位、遮挡关系和事件顺序。

【目标素材职责】
@图片1只用于深灰色电动巡逻车的车身结构、颜色和透明挡风板，不采用图片背景或驾驶员。

【编辑对象与范围】
删除原视频中的红色自行车和骑行者，全片始终只有一辆电动巡逻车。长椅上的两个人、树木、道路和背景保持@视频1。

【时间线继承】
电动巡逻车在完全相同的出现时机、运动路径、速度和遮挡位置覆盖原骑行者的运动槽位。成片中不再出现红色自行车或骑行者；其他人物动作、镜头运动、镜头切换和事件顺序保持@视频1。
```

跨类别动态主体替换优先使用“运动槽位覆盖”：明确删除原主体，让目标主体继承原主体完全相同的出现时机、运动路径、速度和遮挡位置，并声明成片中原主体不再出现。保持清单只写与目标邻接、确实不能变化的区域，避免过长清单稀释编辑目标。

```text
删除@视频1中经过<前景主体>前方的<原动态主体>，在完全相同的出现时机、运动路径、速度和遮挡位置替换为@图片1定义的<目标动态主体>。成片中不再出现<原动态主体>。
```

默认先使用全局母版继承要求。只有原视频中的抓取、交接、放置或进出场能够准确观察时，才增加少量可观察事件条件：

```text
只有当<事件A的可观察完成状态>出现后，才发生<事件B>。
只有当<事件B的可观察完成状态>出现后，才发生<事件C>。
```

不要凭印象把原视频改写成时间段，也不要根据不完整抽帧补写事件条件。Prompt 可以提高关键事件沿用原时间线的概率，但不能承诺编辑后逐帧重合。

## 专项自检

仅对判为视频编辑的画面编辑任务执行：

- 已指定唯一母版、修改范围、目标数量、保持内容和时间线继承。
- 已遵循画幅和基本时长的自动锁定规则；有冲突时仅在 Prompt 后追加一条参数提示。
- 同时要求修改声音时，已读取声音编辑参考，画面和声音修改要求均已保留。
